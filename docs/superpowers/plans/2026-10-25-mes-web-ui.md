# MES 웹 UI (React + FastAPI) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 기존 PostgreSQL MES 위에 FastAPI 백엔드와 React(TypeScript) 웹 UI(대시보드, 공장 현황 Digital Twin 2D, 작업지시, 실적 입력, 설비 제어, LOT 추적)를 만든다.

**Architecture:** `backend/app` 의 FastAPI가 psycopg로 기존 뷰·함수·테이블을 직접 SQL로 조회/입력한다(지표 계산은 SQL, ORM 없음). `frontend/` 의 Vite+React 앱이 `/api` 를 5초 폴링한다. 운영 빌드는 FastAPI가 `frontend/dist` 를 서빙한다. 입력은 기존 INSERT 경로(트리거 포함)를 통과한다.

**Tech Stack:** FastAPI, uvicorn, psycopg 3(기존 `mes.db.connect`), pytest + httpx TestClient / Node.js LTS, Vite, React 18, TypeScript, React Router, TanStack Query, Recharts, vitest + @testing-library/react.

**Spec:** `docs/superpowers/specs/2026-10-25-mes-web-ui-design.md` (기존 DB 설계: `docs/superpowers/specs/2026-10-25-mes-portfolio-design.md`)

## Global Constraints

- 지표(OEE, 불량률, 진행률, LOT 추적)는 SQL(뷰/함수)에서 계산. API·React 는 조회·표시·입력만 (필요한 합계/정렬은 SQL로)
- 입력은 기존 테이블 INSERT 경로와 트리거를 통과해야 하며 우회 금지. 트리거/제약 위반은 HTTP 409 + 한국어 사유(SQLSTATE `23514` CheckViolation, `P0001` RaiseException 로 분류), 잘못된 조합·값은 422, 없는 리소스는 404
- API 접두사 `/api`, JSON. DB 접속은 `mes.db.connect()` (Asia/Seoul 시간대 고정), SQL은 파라미터 바인딩만 사용(문자열 조합 금지)
- UI 라벨·오류 메시지·README 한국어, 코드 식별자 영문. 로그인 없음, 모바일 최적화 없음, AI·WebSocket 없음
- 5초 자동 갱신(TanStack Query `refetchInterval: 5000`)
- 한 설비에는 열린(`ended_at IS NULL`) 상태 로그가 최대 1개 (DB 부분 유니크 인덱스 존재)
- 수동 LOT 번호 형식 `WO-<wo_id>-<공정코드>-M<순번>`; 수동 입력의 교대는 `ended_at` 시각으로 결정, 입력 시각은 서버 현재 시각
- Python: `C:\Users\jeong\anaconda3\python.exe` (PATH 의 `python` 은 스텁). Windows 11. 가상 데이터. Node.js LTS 는 winget `OpenJS.NodeJS.LTS` 로 설치
- 기존 테스트 66개는 마지막 태스크 전까지 계속 통과해야 함

- Produces:
  - `POST /api/work-orders {item_id:int, line_id:int, planned_qty:int>0, due_date:date} -> 201 {"wo_id":int}` (상태 PLANNED; FG/SFG 가 아닌 품목·없는 라인은 422)
  - `POST /api/results {wo_id:int, process_id:int, equipment_id:int, minutes:float=1 (0<m<=60), good_qty:int>=0, defects:[{defect_id:int, kind:"rework"|"scrap", qty:int>0}]=[]} -> 201 {"result_id":int, "lot_no":str}` — 규칙: 작업지시 라우팅에 없는 공정, 작업지시 라인과 다른 설비/공정 불일치, DONE 작업지시, good=0·defects 없음 은 422; 트리거·제약 거부는 409(한국어)

  - `backend.app.services.results.create_result(conn, payload, now: datetime) -> tuple[int, str]` — 한 트랜잭션에서 LOT INSERT(`WO-<wo>-<공정코드>-M<n>`, n 은 같은 작업지시·공정의 기존 `…-M%` LOT 수+1 로 충돌 방지), 직전 공정(같은 작업지시, 라우팅 seq-1)의 가장 최근 LOT 를 `lot_consumption` 으로 연결(첫 공정이면 해당 품목 BOM 의 RM LOT 중 잔량 있는 선입 LOT 에서 소모, 없으면 링크 생략), `production_result` INSERT(`started_at = now − minutes`, `ended_at = now`, `shift_id` 는 `ended_at` 의 로컬 시각이 속한 교대 — 야간 20:00–08:00 처럼 end<start 인 교대 포함), `defect_record` INSERT, `defect_qty = Σqty`, `rework_qty = Σ rework qty`, 호출은 항상 savepoint 안에서 실행하여 실패 시 LOT·링크까지 모두 롤백
