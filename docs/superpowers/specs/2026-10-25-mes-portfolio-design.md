# MES 포트폴리오 프로젝트 설계

## 의도와 이유
LG CNS 스마트팩토리 직무 지원용 포트폴리오. "MES 업무 흐름을 이해하고, 이를 PostgreSQL 데이터 모델과 SQL로 구현하며, 설비 데이터 수집→모니터링까지 연결할 수 있다"는 것을 면접관이 5분 안에 확인할 수 있게 하는 것이 목적이다. DB 설계/SQL 역량이 1순위, 시연 가능성이 2순위.

## 목표
- 정규화된 PostgreSQL 스키마 (품목, BOM, 공정 라우팅, 작업지시, LOT, 설비, 생산실적, 불량, 재고)
- 뷰/함수/트리거/인덱스로 MES 핵심 지표 구현: OEE(가용률·성능률·양품률), 불량률, 작업지시 진행률, LOT 이력 추적(정/역방향), 재고 차감
- Python 시뮬레이터가 설비 가동/생산/불량 데이터를 지속 적재
- Streamlit 대시보드로 실시간 현황 시연
- ERD, 지표 정의, 실행 방법을 담은 README (한국어)

## 비목표
- 작업지시 등록·실적 입력 등 풍부한 데이터 입력 UI (최소한만)
- 인증/권한, 멀티 사이트, 실제 PLC/OPC-UA 연동, 클라우드 배포
- 고도화된 스케줄링(APS)·ERP 연동

## 안티골
- 화면은 그럴듯한데 지표가 SQL이 아닌 Python에서 계산되는 것 (SQL 역량이 안 드러남)
- 스키마가 단순 CRUD 테이블 나열에 그쳐 MES 도메인 이해가 안 보이는 것
- 처음 실행하는 사람이 명령 몇 줄로 재현하지 못하는 것

## 제약
- DB: PostgreSQL. 현재 PC에는 미설치(Python/Anaconda만 있음). Docker가 있으면 Docker, 없으면 네이티브 설치 (내 판단)
- Windows 11, 작업 폴더 `C:\Users\jeong\MES`, git 저장소 아님

## 접근 방식
- **A. DB 중심 + 시뮬레이터 + Streamlit 대시보드** ← 선택
- B. SQL만: 빠르나 시연이 약함
- C. FastAPI+React 풀스택: 완성도 높으나 작업량 크고 DB 비중 희석
선택 이유: 직무 핵심이 도메인 이해와 데이터화이며 A가 SQL 역량과 시연을 모두 충족.

## 결정된 것 (사용자 확인)
PostgreSQL 사용, 방식 A, 대상은 LG CNS 스마트팩토리 직무.

## 내 판단 (확인 필요)
- 가상 공장: 전자부품 SMT/조립 라인 (공정: 자재투입→SMT→AOI검사→조립→기능검사→포장). 스마트팩토리 사례로 친숙함
- 대시보드는 Streamlit (Python 단일 스택으로 단순)
- DB 접근은 psycopg 직접 사용, ORM 미사용 (SQL이 코드에 드러나도록)
- SQL 파일은 `sql/` 아래 번호순(스키마→시드→뷰→함수→트리거) 관리, 마이그레이션 도구 미사용
- 샘플 데이터: 시드 SQL + 시뮬레이터 생성 혼합, 모두 가상

## 지표·도메인 정의 (내 판단, 검토 단계에서 보강)
- **OEE** = 가용률 × 성능률 × 양품률. 가용률 = (계획시간 − 비가동시간) / 계획시간, 성능률 = (이론 사이클타임 × 총생산수량) / 가동시간, 양품률 = 양품수량 / 총생산수량. 이론 사이클타임은 공정 라우팅 단계(품목×공정)별로 보관. 계획 비가동(점심·점검)은 비가동 사유 코드의 '계획' 구분으로 제외. 집계 단위는 설비×교대(주간/야간) 및 일 단위
- **불량률** = 공정별 불량수량 / 투입수량, 종합 직행률(FTY)도 제공. 불량은 재작업(rework)과 폐기(scrap)를 구분
- **작업지시 진행률** = 최종 공정 양품수량 / 지시수량
- **LOT 추적**: 공정마다 LOT가 생성되고 부모-자식 소모 관계 테이블로 연결. 원자재 LOT(공급사 LOT)에서 완제품 LOT까지 정방향·역방향 재귀 쿼리(WITH RECURSIVE)로 추적. 개별 시리얼 번호는 제외
- **재고 차감**: 생산실적 등록 시 트리거가 BOM 소요량 × (양품+불량) 수량을 원자재 재고에서 차감(backflush), 완제품은 양품 수량만큼 증가. 재고는 잔고 테이블 + 입출고 이력(원장) 구조, 창고 위치는 단일, 음수 재고는 제약으로 차단
- **시뮬레이터**: 주기(사이클) 단위 생산실적과 설비 상태 변경 이벤트를 적재. 배속 옵션(기본 실시간의 수십 배)으로 시연. 대시보드는 5초 폴링. 지표는 일반 뷰로 시작하고, 느리면 머티리얼라이즈드 뷰 적용
- **재현성**: docker-compose 파일 제공(PostgreSQL 16) + Docker가 없으면 네이티브 설치 안내. 실행은 README의 몇 줄 명령. 면접관이 직접 돌리지 않아도 되도록 스크린샷도 README에 포함
- **언어**: 테이블/컬럼명은 영문 snake_case, 주석·화면 라벨·README는 한국어
- **규모**: 품목 약 10개(완제품 3, 반제품 2, 원자재 5), 라인 2, 설비 약 10대, 작업지시 수십 건
